# 응급실·중증질환 진료불가 메시지

> 출처: 병원정보 검색 API(제공처 GGFI) 개발서버 실측(2026-10-30, 전국 응급실 414곳), 원천 테이블 `tapi_emrm_nd_svredss_msg_inq`(응급실및중증질환메시지조회, [erd_hospital.mmd](../10_설계/erd_hospital.mmd))

응급의료기관은 진료할 수 없거나 진료를 제한하는 내용을 메시지로 등록한다. 국립중앙의료원 응급의료 데이터는 이 메시지를 "차단 메시지"(`symBlkMsg`)라고 부르고, 메시지마다 차단 시작 시각과 차단 종료 시각을 둔다. 병원정보 검색 API는 이 메시지를 병원 상세의 `publicStatusMessages`로 준다.

## 1. 메시지 필드

| API 필드 | 원천 컬럼 | 뜻 | 실측 값 |
|---|---|---|---|
| `message` | `symblkmsg` | 병원이 쓴 메시지 문장 | 자유 문장. 가장 긴 것은 129자 |
| `messageType` | `symblkmsgtyp` | 메시지 구분 | `응급` 543건, `중증` 181건 |
| `symptomTypeCode` | `symtypcod` | 메시지가 가리키는 대상 코드 | `Y000`(응급실)과 중증질환 코드 27종(아래 2절) |
| `symptomTypeName` | `symtypcodmag` | 대상 코드의 이름 | 예: `응급실`, `심근경색의 재관류중재술` |
| `displayYn` | `symoutdspyon` | 메시지 종류로 보인다(아래 3절) | 724건 모두 `차단` |
| `displayMethod` | `symoutdspmth` | 메시지를 등록한 방식으로 보인다 | 724건 모두 `자동` |
| `startDateTime` | `symblksttdtm` | 차단 시작 시각 (`yyyyMMddHHmmss`) | 빈 값 없음 |
| `endDateTime` | `symblkenddtm` | 차단 종료 시각 (`yyyyMMddHHmmss`) | 빈 값 없음 |

API 필드와 원천 컬럼의 대응은 GGFI가 알려 준 것이 아니다. 필드 9개가 하나씩 짝이 맞는 것을 보고 추정했다. ERD는 `symoutdspyon`을 "중증질환 표출구분", `symoutdspmth`를 "표출 차단구분"이라고 설명하는데, 실측 값(`차단`, `자동`)과 비교하면 두 설명이 서로 바뀐 것으로 보인다.

## 2. 응급 메시지와 중증 메시지

- **응급 메시지**(`messageType=응급`)는 응급실 진료 전체에 대한 메시지다. 대상 코드는 모두 `Y000`(응급실)이다. 진료과별 진료 가능 시간, 받을 수 있는 환자의 연령, 사전 문의가 필요한지 같은 내용을 담는다.
  - 예: `[정신건강의학과] 정신과적 응급입원 평일 9A~6P만 가능 이외 주말 및 공휴일 수용불가능` (분당서울대학교병원)
  - 예: `평일 08시~18시, 토요일 08~13시 이외 진료 불가(24개월 미만 진료불가)` (안양샘병원)
- **중증 메시지**(`messageType=중증`)는 중증질환 한 종에 대한 메시지다. 대상 코드는 아래 27종 중 하나다. 병원이 같은 문장을 여러 질환에 등록하면 API는 질환마다 메시지를 한 건씩 준다.
  - 예: `담당 전문의 부재로 응급 ERCP불가` → 담낭담관질환(담낭질환) (원광대학교산본병원)
  - 예: `일시적 불가` → 산부인과 응급(분만), 산부인과 응급(산과수술), 산부인과 응급(부인과수술) 세 건 (한림대학교동탄성심병원)

**중증질환 코드 (실측 27종):**

| 코드 | 이름 | 코드 | 이름 |

## 3. `displayYn`의 `차단`

`차단`은 이 메시지가 "진료 차단(불가)을 알리는 메시지"라는 뜻으로 본다. 원천 데이터가 메시지를 "차단 메시지"라고 부르고, 기간도 "차단 시작"과 "차단 종료"로 적기 때문이다. 이 해석은 GGFI에 문의 중이며 아직 확정되지 않았다.

다만 메시지 문장이 모두 "불가"를 뜻하지는 않는다. 아래 메시지들도 `displayYn`이 `차단`이다.

- `외상성 뇌출혈 수용 가능` → 뇌경색의 재관류중재술, 뇌출혈수술(거미막하 출혈) (가톨릭대학교의정부성모병원)
- `[정형외과] 사지접합술 제외한 응급수술 가능` (분당서울대학교병원)

그래서 진료 가능 여부는 `displayYn`이나 `messageType` 값으로 판단할 수 없고, 메시지 문장을 읽어야 알 수 있다. 개발서버에는 `차단`이 아닌 값이 없었다. 다른 값이 있는지도 GGFI에 문의 중이다.

## 4. 메시지 문장의 특징

- **사유 없는 "불가" 표시가 많다.** 중증 메시지 181건 중 90건의 문장이 `불가능메세지등록`이다. 병원이 사유를 쓰지 않고 중증질환을 "불가"로만 표시하면 이 문장이 들어가는 것으로 보인다. 이 경우에는 그 병원이 해당 질환을 진료할 수 없다는 사실만 알 수 있다.
  - 예: 화성중앙종합병원은 중증질환 27종 모두에 `불가능메세지등록`을 등록했다.
- **머리표 형식이 병원마다 다르다.** 진료과를 문장 앞에 붙일 때 `[신경외과]`, `[ENT]*`, `<소아전문응급의료센터>`처럼 병원마다 다른 형식을 쓴다. 진료과를 붙이지 않는 병원도 있다.
- **시간대 표기가 병원마다 다르다.** `9A~6P`, `08:00~ 18:00`, `08시~18시`, `정규 시간 외 17시~08시`처럼 쓴다.
- **차단 기간은 보통 일주일 안팎이다.** 응급 메시지 543건 중 445건, 중증 메시지 181건 중 106건의 차단 기간이 6~8일이다(예: 10-24 ~ 10-31). 하루가 안 되는 메시지도 응급 17건, 중증 25건 있다(예: 경기도의료원이천병원 `08:30-13:30 심근경색 재관류 불가`, 10-30 09:10 ~ 13:30).
